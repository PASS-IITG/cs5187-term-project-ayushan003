# Defects

Four defects in Turso's string functions, all found by this tool and all fixed
upstream by our patches. Each has its own directory with a reproduction, the
measured before-and-after, the root cause, and the seed that rediscovers it.

| # | Defect | Reproduction | Upstream |
|---|---|---|---|
| [**1**](defect-01-lpad/README.md) | `lpad` allocates before validating the length | `select LPAD('a', 9223372036854775807, 'b')` | [#11219](https://github.com/tursodatabase/turso/issues/11219) → PR [#11225](https://github.com/tursodatabase/turso/pull/11225) **merged** |
| [**2**](defect-02-rpad/README.md) | `rpad` allocates before validating the length | `select RPAD('a', 9223372036854775807, 'b')` | same |
| [**3**](defect-03-repeat/README.md) | `repeat` overflows its size computation | `select repeat('a', 9223372036854775807)` | same |
| [**4**](defect-04-multibyte-fill/README.md) | the length guard counts characters against a byte limit | `SELECT length(LPAD('a', 1000000000, '😀'))` | [#11260](https://github.com/tursodatabase/turso/issues/11260) → PR [#11259](https://github.com/tursodatabase/turso/pull/11259) **merged** |

A copy-pastable write-up of all four is in [`SUMMARY.md`](SUMMARY.md). The
patches, pull-request bodies and issue texts are in
[`patches/`](patches/).

## Why upstream has two patches and not four

**Defects #1–#3 share one fix.** `exec_lpad` and `exec_rpad` both delegate to
the shared `pad()` body, so #1 and #2 are one root cause reached through two
SQL entry points — each able to abort the process on its own, which is why both
are listed, and not two independent bugs, which is why this paragraph exists.
`exec_repeat` is a separate function with the same class of defect plus an
unchecked multiply.

Moving the limit check in front of the allocation in both places closes all
three, so they were filed as one issue and one patch. That patch carries one
regression test per code path:
`pad_rejects_a_length_over_the_limit` and
`repeat_rejects_a_count_that_overflows_the_limit`.

**Defect #4 is a different root cause in the same function**, with its own fix,
issue and patch. It became reachable only once #1–#3 were fixed: with the guard
finally running before the allocation, the guard itself turned out to be
comparing characters against a byte limit.

## Oracle signatures

The oracle groups hits by a coarse signature, so one signature can cover more
than one SQL entry point into the same abort. `64513113c675` covers defects #1
and #2 for that reason. The signature is a grouping hint for triage, never a
claim about how many defects exist — that judgement is made by reading the code,
and the reasoning is in each defect's own page.
